  1. 1새 열 — 맨 오른쪽 점선 칸에 컬럼 이름을 적으면 열이 생깁니다. 이름 대신 값부터 적어도 되고, 그러면 col1 같은 임시 이름이 붙습니다(위로 올라가 이름을 고치면 됩니다). 비워 두면 JSON에 나오지 않습니다. 머리줄은 이름 줄과 그 아래 타입 줄(타입·버튼)로 나뉘고(세로 보기에서는 왼쪽의 이름 열·타입 열), 이름이 길면 그 길이만큼 열이 저절로 넓어집니다.
  2. 2새 행 — 맨 아래 점선 줄에 적으면 행이 생깁니다. Name처럼 ID가 아닌 칸부터 적으면 ID는 가장 큰 번호의 다음 번호가 자동으로 붙습니다. 마지막 행에서 Enter를 치면 그 줄로 내려가고, 긴 표에서는 Ctrl+↓로 한 번에 갑니다.
  3. 3열 타입 — ID · String(문자열) · Int(정수) · Float(실수) · Bool(참/거짓) · Enum(정해진 값 중 하나). 드롭다운에 마우스를 올리면 타입 설명이 보입니다. JSON에 그 타입 그대로 나갑니다("900"이 아니라 900). 새로 만든 열은 처음 적은 값을 보고 타입이 자동으로 정해지고, 드롭다운에서 언제든 바꿀 수 있습니다. 타입을 바꿔도 칸의 값은 그대로이고, 맞지 않는 값만 빨간 칸으로 알려줍니다(Bool 열은 값이 true · false · 빈칸일 때만 체크박스).
    Enum은 엑셀처럼 칸에 바로 적습니다. 그 열에 적힌 값들이 곧 값 목록이고, 앞 글자만 쳐도 나머지가 흐리게 보여 Enter·Tab으로 채워집니다(그대로 두려면 Backspace나 Delete). 옆의 ⚙를 누르면 지금 목록이 보입니다. 잘못 적은 값은 칸을 고치면 목록에서도 사라집니다. JSON에는 글자로 나갑니다.
  4. 4빨간 칸 — 타입에 맞지 않는 값입니다(위 표의 천원). 위쪽에 오류 개수가 뜨고, 고치면 사라집니다.
칸 고르기와 고치기 (엑셀과 같음) — 칸을 클릭하면 고른 상태가 되고, 화살표로 옆 칸으로 움직입니다. 그대로 타이핑하면 기존 값을 지우고 새로 쓰고, 기존 값을 일부만 고치려면 더블클릭이나 F2. 고치던 것은 Esc로 취소, 고른 칸은 Delete로 비웁니다. 여러 칸은 드래그해서 고르고(컬럼 이름 칸이나 행 번호를 끌면 열·행 통째로) Ctrl+C로 복사하거나 Delete로 한꺼번에 비우며, 잘못 고친 것은 Ctrl+Z로 되돌립니다. 열 순서는 컬럼 이름 칸을 꾹 눌러 끌어서 바꿉니다. 대사처럼 긴 글을 적으면 칸(열)이 글자에 맞춰 넓어집니다. 컬럼 이름 칸의 오른쪽 경계를 끌면 열 너비를 직접 정하고(컬럼 이름보다 좁게는 안 줄어듭니다), 두 번 누르면 다시 글자에 맞춥니다. 칸을 고르면 그 줄의 행 번호와 컬럼 이름 칸이 칠해지고, 그 줄 · 그 열이 옅게 표시됩니다. 키 전체는 보기 · 단축키에 있습니다.
이미 엑셀로 만든 표가 있다면 — 엑셀에서 Ctrl+A, Ctrl+C 한 뒤 GameTableMaker의 빈 곳을 누르고 Ctrl+V. 첫 줄이 컬럼 이름이 되고, 값을 보고 열 타입을 알아서 정합니다. 엑셀이 붙이는 1,000 같은 쉼표와 TRUE/FALSE도 알아봅니다.

ID 규칙

첫 열이 ID입니다. JSON에는 정수로 나가고, 행은 항상 ID 순서로 정렬됩니다.

  1. 1ID는 정수 — 번호에 의미를 담는 방식(1011 씨앗, 1012 작물…)을 그대로 씁니다. 비었거나, 숫자가 아니거나, 다른 행과 겹치면 빨간 칸입니다.
  2. +번호 이어서 적기 — ID 칸에 1001을 적고 Enter를 치면 맨 아래 빈 줄에 1002가 미리 채워집니다. 그대로 Enter면 1002 행이 생기고, 2001처럼 다른 번호를 치면 그다음부터 2002, 2003…으로 이어집니다. 이미 있는 번호는 건너뜁니다.
  3. 2⚙ 접두사 — item_처럼 적으면 칸 앞에 이름표가 붙어 어떤 테이블의 ID인지 보입니다. 화면에만 붙고 JSON에는 1001로 나갑니다. JSON에 포함을 켜면 "item_1001" 문자로 나갑니다. 설정이 있으면 ⚙가 파랗게 보입니다.
  4. 3정렬 — ▼ 오름차순, ▲ 내림차순. 번호를 적고 칸을 떠나면 그 행이 순서에 맞는 자리로 갑니다.
  5. 4노란 칸 — 다른 테이블이 같은 자릿수의 ID를 쓰고 있다는 알림입니다(위 표의 2001). 테이블마다 100단위, 1000단위처럼 자릿수를 나눠 쓰면 겹치지 않습니다. 저장은 막지 않습니다.
ID가 없는 테이블 — Config처럼 한 줄짜리 설정 테이블은 ID 열을 지우면 됩니다. 다른 열의 타입을 ID로 바꾸면 그 열이 맨 앞으로 가서 ID가 됩니다.

  1. 1켜기 — ID 열의 ⚙ → 다른 테이블 참조를 체크하면, 이 테이블의 ID가 들어 있는 테이블이 자동으로 골라집니다. 아래 목록에서 체크로 바꿀 수 있고, 여러 개도 됩니다(예: CostDataTable → StructureDataTable + UnitDataTable). 대상도 탭으로 열려 있어야 합니다.
  2. 2🔗 자동으로 가져온 열 — 대상에도 있는 이름의 열(Name)은 같은 ID 행의 값으로 채워지고 회색으로 잠깁니다. 대상에서 고치면 여기도 바뀌고, JSON에도 그 값으로 나갑니다.
  3. 3🔗 끄기 — 파란 🔗를 누르면 연결이 끊겨 직접 고칠 수 있습니다. 연결 전에 적어 둔 값이 있었다면 그 값으로 돌아갑니다. 다시 누르면 대상 값으로 채워집니다.
  4. 4없는 ID — 고른 대상 어디에도 없는 번호는 노란 경고 칸입니다(1099). 오타나 지워진 아이템을 찾을 때 씁니다. 이 테이블에만 일부러 둔 행이면 칸을 우클릭 → 이 경고 숨기기로 숨길 수 있고(다시 우클릭하면 되살리기), 오류로 치지 않아 저장도 그대로 됩니다.

불러오기 · 저장

어디서 가져오든 같은 목록 창이 떠서, 파일마다 들어갈 곳(새 탭 · 설명 · 설정)을 먼저 짐작해 보여 줍니다. 지금 탭은 덮어쓰지 않습니다.

  1. 1GitHub — 팀 저장소의 폴더에서 바로 가져옵니다. 로그인 · 연결 · 갱신은 팀으로 쓰기에 정리했습니다.
  2. 2파일 — 여러 개를 함께 고를 수 있습니다. JSON · CSV 하나만 고르면 목록 창 없이 바로 새 탭으로 열립니다.
  3. 3폴더 — Unity의 Json 폴더를 통째로 고르면 안의 파일이 목록에 나옵니다(.meta · 엑셀은 뺌). 이름 순서로 열리니 탭을 끌어 순서를 바꾸세요.
  4. 4JSON… · 설명서… — 저장할 탭을 고릅니다. 하나면 파일 하나, 여러 개면 zip 하나. 오류가 있으면 먼저 묻습니다.
  5. 5프로젝트 전체 — 모든 탭의 JSON · 설명서와 설정 메모 _TableMaker.md(탭 순서 · 보기 · 숨긴 경고)를 zip 하나로. 다시 불러오면 그대로 열립니다.
  6. 6GitHub에 커밋 — 고친 내용을 팀 저장소에 올립니다. 팀으로 쓰기 참고.

처음 한 번

1저장소 준비

GitHub에 저장소를 만듭니다(내 계정이든 조직이든 됩니다). 만들 때 Add a README file을 체크하면 빈 저장소가 아니라서 문제가 없습니다. 팀원은 저장소 Settings → Collaborators(조직이면 조직)에 초대합니다.

2앱 설치 (저장소 주인, 한 번)

저장소 주인이 GameTableMaker 앱을 설치하고 쓸 저장소를 고릅니다. 처음 GitHub로 로그인하면 Authorize 다음에 바로 앱 설치 화면으로 이어져, 저장소를 고르고 Install하면 돌아옵니다. 팀원이 초대한 저장소만 쓴다면 로그인 창의 앱 설치 없이 로그인을 누르세요. 로그인 뒤 주인에게 설치를 부탁하는 안내(공유하기 · 복사)가 뜹니다. 앱은 고른 저장소의 파일 읽기 · 쓰기만 합니다.

3로그인 (각자)

☰ → GitHub 로그인 → GitHub로 로그인을 누르고 GitHub 화면에서 Authorize를 누르면 돌아옵니다. 토큰을 만들 필요가 없습니다. 로그인 유지(기본 켬)를 끄면 탭을 닫을 때 로그아웃됩니다. 직접 만든 토큰을 쓰고 싶으면 같은 창의 고급: 토큰으로 로그인.

4연결

불러오기 ▾ → GitHub으로 저장소 · 브랜치 · 폴더를 고르면 가져오면서 연결됩니다. 처음 올리는 사람은 파일 저장 ▾ → GitHub에 커밋으로 연결해도 됩니다. 이미 작업하던 표가 있으면 같은 창의 현재 표로 연동을 누르세요. 지금 탭은 그대로 두고 연결만 하고(중복 탭이 생기지 않음), GitHub에만 있는 표는 받아 옵니다. 내용이 다른 표는 다음 커밋 때 올릴 목록에 나옵니다. 연결된 프로젝트에서 불러오기 · 커밋 창을 열면 연결된 저장소 · 브랜치 · 폴더가 먼저 채워져 있고, 저장소를 다른 것으로 바꾸면 브랜치 · 폴더는 기본값(기본 브랜치 · 맨 위)으로 돌아갑니다.

  1. 4내가 고친 파일만 — 마지막 갱신 뒤 고친 파일만 올라가서, 팀원이 고친 파일을 옛 내용으로 되돌리지 않습니다. 고치는 동안은 브라우저에만 저장되고, 커밋해야 팀원에게 보입니다. 상태에는 GitHub 파일과 데이터를 직접 비교한 결과(바뀐 칸 수, 더하거나 뺀 줄)가 한 줄로 나오고, 상태를 누르면 드롭다운처럼 아래로 펼쳐져 1001 · Name: "Sword" → "Blade"처럼 하나하나 보입니다(다시 누르면 접힘). 들여쓰기 · 띄어쓰기 같은 글자 모양은 바뀐 것으로 치지 않고, GitHub 파일 모양(들여쓰기 칸 수, "ID":10처럼 붙여 쓰기, 1.0 같은 소수점)을 그대로 따라 써서 GitHub에도 고친 줄만 바뀐 것으로 보입니다. 원래 빈 값이 null이던 컬럼은 null 그대로 나갑니다.

  4. 7커밋 메시지 — 여러 줄로 씁니다. 첫 줄은 제목, 아래는 자세한 설명입니다. 창을 열면 GitHub 파일과 비교해 프로그래머가 알아야 할 변경(⚠ 컬럼 이름 변경 · ⚠ 컬럼 삭제 · ⚠ 타입 변경 · 컬럼 추가 · 새 테이블)이 컬럼 이름까지, 데이터 변화는 컬럼별로 바뀐 칸 수와 더하거나 뺀 줄의 ID로 미리 적혀 있습니다. 줄은 ID로 맞추고(101과 "101", ID 컬럼 이름이 바뀐 경우도 같은 줄), 번호를 새로 매겼으면 순서로 맞춥니다. 올릴 파일을 바꾸면 다시 적히고, 직접 고쳐 쓰기 시작하면 그대로 둡니다. 이용 안내

GameTableMaker를 쓰기 전에 알아두면 좋은 점입니다.

프로젝트

제목줄 왼쪽의 프로젝트 이름을 누르면 프로젝트를 바꾸거나, 새로 만들거나, 이름을 바꾸고 지울 수 있습니다. 새로 만들 때는 빈 프로젝트 · 내 파일로 시작 · GitHub 저장소에서 중 하나를 골라 확인 버튼으로 시작합니다(처음 열면 이 창이 뜨고, 첫 칸은 예시로 둘러보기). 탭 묶음은 프로젝트마다 따로 저장됩니다.

데이터는 내 브라우저에만

입력한 표는 서버로 보내지 않고 지금 쓰는 브라우저에만 저장됩니다. 가입도 필요 없습니다. 브라우저 저장 공간은 모든 프로젝트를 합쳐 글자 약 500만 자까지라, 아주 큰 프로젝트로 꽉 차면 알림이 뜹니다. 꽉 찬 동안은 고친 내용이 저장되지 않으니(새로고침하면 마지막으로 저장된 때로 돌아갑니다) 바로 zip으로 받아 두고, 안 쓰는 프로젝트나 테이블을 지우세요.

백업은 직접

브라우저 데이터를 지우거나 다른 PC로 옮기면 표가 보이지 않습니다. 중요한 작업은 파일 저장 ▾ → 프로젝트 전체 (.zip)로 받아 두거나 GitHub에 커밋하세요.

Safari에서 쓸 때

Safari(Mac · iPhone · iPad)는 이 사이트를 Safari를 쓴 날로 7일 동안 열지 않으면 브라우저에 저장된 표를 지울 수 있습니다(Apple의 개인정보 보호 정책, 사이트에서 끌 수 없습니다). 크롬 · 엣지 · 파이어폭스에는 이런 규칙이 없습니다. Safari에서 쓴다면 GitHub 저장소에 연결해 커밋하거나(커밋한 것은 저장소에 남습니다) 프로젝트 전체 (.zip)로 받아 두세요. 받아 둔 지 3일이 지나면 열 때 알림이 뜹니다. iPhone · iPad는 공유 → 홈 화면에 추가로 열면 이 규칙이 적용되지 않습니다. Mac의 파일 → Dock에 추가도 앱처럼 열리지만 이 규칙에서 빠지는지는 Apple이 밝히지 않았으니, 받아 두기를 함께 하세요.
